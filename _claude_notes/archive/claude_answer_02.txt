Q3 — the restart is required, and the reason is a bug I can fix

I found the cause rather than guessing at it:

@lru_cache(maxsize=8)                      # server/app/drawing.py:40
def load_circuit_logic(drawing_dir): ...

The three authored files each clear their own cache when the server writes them — load_locations.cache_clear(), load_wiring.cache_clear(), load_corrections.cache_clear(). The generated
netlist has no writer inside the server, so nothing ever clears its cache. You rning process keeps handing out the copy it read at startup. The restart is not aUI limitation; it is an un-invalidated cache.

Three ways forward, and I would do the first two:

1. Key the netlist cache on the file's mtime so it re-reads a regenerated artifact by itself. Ten lines and one server test. After that, the loop is run the commands, reload the browser — no
   restart.

   lands.
